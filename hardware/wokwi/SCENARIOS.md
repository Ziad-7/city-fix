# Reproducible Wokwi scenarios

Run each scenario in its matching free ESP32 Arduino browser project at Serial Monitor **115200 baud**. These are expected behaviors from source and the local host harness; the browser simulation itself was not available in this workspace.

## Smart bin

1. **Distance and threshold equality:** start at the diagram's 24 cm (about 80%); Serial reports fill near 80%. Change the HC-SR04 control to 100 cm (0%) and 5 cm (100%). Set temperature to 59 °C, then exactly 60 °C. Full and heat flags are independent and may both be on. Holding above a threshold does not repeat the edge send; sample below it and then return to equality to re-arm/retrigger. A disconnected/invalid sensor shows `SENSOR FAULT`; it never queues a made-up empty value.
2. **Queue during outage:** switch network off, then run `sample` or use SAMPLE NOW for normal/full/hot/normal readings. `status` prints immutable JSON rows and stable sequence numbers. Restore the network switch, or issue `network on`; queued rows are retried in batches up to eight. `mock partial` accepts only part of the next batch. `mock fail-next` commits at the local receiver, withholds the response, and demonstrates idempotent retry. `mock bad-ack` returns an unknown sequence; no queue row is deleted. Restart the Wokwi simulation to exercise its actual NVS behavior separately—do not assume stopping/recreating a browser simulation preserves data.
3. **Policy application and cadence:** issue `mock policy 1 50 45`, then take a reading. `status` still shows the device's prior thresholds until the next valid response; after ACK, equality at 50%/45 °C activates the new flags and fast scheduling uses 1 second (real timing uses one minute). `timing real` and `timing fast` do not change wire values.
4. **Power and solar state:** turn battery potentiometer through about 3.4 V and 3.1 V. Below 3.4 V sampling slows. Below 3.1 V, the display says `LOW POWER`, sends pause, and queued readings remain. Raise it to recover. Toggle solar/daylight; the CHARGING LED is on only if solar is on and battery is below 4.15 V. These are illustrative states, not a battery or solar electrical simulation.
5. **Optional real HTTP:** use Serial `mode http`, `endpoint <baseURL>`, `key <fresh-disposable-key>`. HTTPS stays CA-verified if a valid public `root_ca.h` is present. `tls insecure-demo` explicitly displays its unverified status and is for a disposable tunnel only. The Wokwi gateway to the PC adapter through a public tunnel was not tested here; use README tunnel limits.
6. **Capacity and persistence:** repeatedly sample offline until 32 rows. The next sample says `QUEUE FULL`, does not consume another sequence, and never overwrites queued alert rows. Reboot the simulation and verify what the Wokwi model actually restores; firmware's Preferences/NVS record is checksummed and append/sequence plus ACK/policy writes are saved together.

## Collection-hub scale

1. Start with no zero calibration. The display says tare/calibration needed, and confirm does not queue a guessed weight.
2. Leave the virtual load at zero, press TARE (or type `tare`), and wait for the bounded reads. Apply a known load in the Wokwi HX711 control, run `calibrate 5` for the chosen 5 kg reference, then change the load and check the shown kilograms. Calibration is simulated and makes no accuracy claim.
3. Set `material pet_plastic` (the exact supported values are `pet_plastic`, `paper_cardboard`, `metal_cans`, `glass`, `e_waste`, `cooking_oil`, and `organics`), optionally `pickup pickup-demo-1`, then press CONFIRM once or type `confirm`. Unsupported or case-mismatched material values are rejected without changing the current selection. Serial shows one immutable payload. Holding or bouncing the button does not create duplicates. `pickup clear` removes the optional pickupId. Invalid/nonpositive known weights, unavailable HX711, uncalibrated, negative, nonfinite, or unstable confirmed weights are rejected.
4. Switch network off, confirm additional weighings, and inspect the pending queue. Restore it and observe an explicit **LOCAL MOCK** ACK. `mock fail-next` stores the local mock's accepted sequence but loses its response; retry identifies the duplicate and ACKs the same weighing. The local ACK is never described as backend or HTTP delivery.
5. Reboot and check persisted sequence, pending rows, tare, and calibration. As with the bin, actual Wokwi browser stop/recreate retention must be tested rather than assumed.
